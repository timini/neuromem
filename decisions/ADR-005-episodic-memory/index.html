    ADR-005: Episodic memory, whole-memory embeddings and dated episode clusters¶

    Status: Proposed (experimental, runs alongside the tag pipeline) Date: 2026-11-25 Extends: ADR-003 (ontology tree v2), ADR-004 (hot-path split)

    Context¶

    The tag pipeline (ADR-001 to ADR-004) embeds short LLM-extracted tag labels, clusters those label vectors with HDBSCAN and names each centroid with an LLM. A review of the LongMemEval_S seed-42 run (0.746 under the official judge prompts on gemini-3.8-flash; 0.729 with gemini-2.5-flash as judge) found:

    • Most misses were not retrieval misses. The relevant session was in the rendered context.
    • No dates reached the system. Session timestamps and the question date were dropped by the runner, so "how many days ago" was unanswerable and knowledge-update questions had no way to tell the old value from the new one.
    • Summaries were short and user-centric, so details the assistant gave (a list item, a number, a chess move) were lost.
    • A memory appeared under several tags, so about a third of rendered rows were duplicates.
    • Centroid vectors were means of 1 to 4 word label vectors, which drift towards generic centres.

    Decision¶

    Add neuromem.episodic.EpisodicMemory, a second memory model, without changing NeuroMemory.

    D1: no labels; a memory is a whole session, stored with its date¶

    enqueue_session(turns, timestamp=..., session_id=...) stores the transcript, the session date and a sort key. The summary prompt is given the session date and must resolve relative dates ("last Saturday") to absolute ones, keep every personal fact, state changed values explicitly, and keep the concrete specifics the assistant gave.

    D2: embed the whole memory¶

    Each memory is embedded as date + summary + full transcript. Embedding APIs truncate long input silently (both gemini-embedding-001 and gemini-embedding-2 accept 40K characters without error), so text over embed_chunk_chars is split into chunks that each carry the date and summary header; the chunk vectors are normalised and averaged. The default embedder is gemini-embedding-2 (8K-token input).

    D3: merge near-duplicates in the dream cycle¶

    Memories whose embeddings have cosine similarity at or above merge_threshold (default 0.97) are grouped by union-find into one unit. The unit keeps every member's date and raw transcript and gets one merged summary that orders events by date and puts the latest value first. A unit's merged summary is regenerated whenever its member set changes.

    D4: many overlapping episodes from several dendrograms¶

    For each linkage method in linkages (default average and ward), build the full agglomerative dendrogram over the unit embeddings with scipy. Every internal node becomes an episode; identical member sets from different linkages are kept once. With N units this gives up to len(linkages) * (N - 1) episodes, and each memory belongs to several episodes at different granularities. Episodes larger than max_episode_size are skipped.

    D5: episode summaries are chronological and lead with the current state¶

    Each episode is summarised from its members' dated summaries, in date order, in a fixed format: TOPIC, CURRENT (latest state of everything that changed, with dates), HISTORY (one dated line per member). Summaries are cached by the set of member memory ids, so a later dream cycle only summarises new member sets.

    Each episode stores two vectors: the embedding of its summary text and the normalised mean of its member embeddings. Retrieval can score with either or the maximum. A sum of member vectors ranks the same as the mean under cosine similarity, so it is not offered separately.

    D6: retrieval¶

    Score units and episodes against the query embedding. Render today's date, the top episodes (skipping any whose member set overlaps a higher-ranked one by more than 0.8 Jaccard), the top units in date order with their dates, and the raw transcripts of the closest units.

    D7: scipy becomes a declared dependency¶

    scipy.cluster.hierarchy.linkage provides the dendrograms. scipy is already installed as a dependency of hdbscan (ADR-003); it is now declared in neuromem-core because the code imports it directly.

    Consequences¶

    • Dates flow end to end: runner, agent, memory, summaries, render and answer prompt.
    • Dream cost grows with the number of episodes: one LLM call per new member set, each over up to max_episode_size member summaries. Workers run these calls in parallel.
    • Storage is self-contained (its own SQLite tables) rather than going through StorageAdapter. If the model is adopted, the adapter contract needs memory embeddings and episode records.
    • Episode summaries are rebuilt only when membership changes, so a unit whose summary changes without a membership change keeps older episode text until its set changes.
    • The comparison with the tag pipeline is not only a model comparison: the episodic agent also gets dates, a different embedder and a different answer prompt. Results are reported with that caveat.
