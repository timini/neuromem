    Benchmark results¶

    All results are on LongMemEval_S (Wu et al., ICLR 2025). Each question comes with a chat history of about 50 sessions (about 115K tokens). The agent reads the history session by session, then answers one question about it.

    The head-to-head run is incomplete and not stratified

    Both head-to-head runs stopped at 10:48 UTC on 2026-11-25, when the Gemini project reached its monthly spending cap. Before that, 16 instances finished validly for both agents. The numbers below are those 16 paired instances. They are not a balanced sample: 6 are multi-session questions, 3 knowledge-update, 3 single-session-user, 2 temporal-reasoning, 1 single-session-assistant and 1 preference. The page will be updated when the full 60-instance runs complete.

    Not merged yet

    EpisodicMemory, the neuromem-episodic benchmark agent and the official judge are on the episodic-memory-v2 branch and are not yet in main.

    Method¶

    Setting Value
    Dataset LongMemEval_S, cleaned release (xiaowu0162/longmemeval-cleaned)
    Sample 10 questions per type, 6 types, shuffled with seed 42 (--per-type-sample 10 --seed 42)
    Answer and memory model gemini-3.8-flash (head-to-head); gemini-3-flash-preview (earlier runs)
    Judge LongMemEval's official per-type judge prompts, run on gemini-3.8-flash at temperature 0
    Scoring Correct if the judge's reply contains "yes", as in the official evaluator

    The judge¶

    Earlier runs used one generic prompt ("is the prediction correct?") on gemini-2.0-flash-001, a model that has since been retired. The harness now uses the official LongMemEval prompts, copied verbatim from src/evaluation/evaluate_qa.py:

    • Abstention questions (ids ending in _abs) are correct if the model says the information is not available.
    • Temporal reasoning does not penalise off-by-one errors in day counts.
    • Knowledge update accepts an answer that mentions the old value as long as it gives the updated one.
    • Preference questions are graded against a rubric, not an exact answer.

    Rescoring the existing seed-42 run with the official prompts changed 8 of 59 verdicts. Some false negatives became correct (for example "Your sister gave you…" against the gold "my sister") and some false positives became wrong (7 days against a gold of 18). The judge model matters too: the same predictions score 0.729 with gemini-2.5-flash as judge and 0.746 with gemini-3.8-flash.

    Sample size¶

    Ten questions per type is small. The 95% Wilson interval for 44 correct out of 59 is 0.62 to 0.84, and for a single type at 6 out of 10 it is 0.31 to 0.83. Differences of a few points between runs are noise. Comparisons below are paired: both agents answer the same instances.

    The three questions only the episodic agent got right show the mechanisms at work:

    Question Gold Episodic Tag-graph
    How many sessions of the bereavement support group did I attend? (knowledge update) five "5 sessions (noted on October 30, 2023, updating your earlier mention of 3 sessions on May 11, 2023)" "three"
    What percentage of leadership positions do women hold in my company? (multi-session) 20% "20% (20 out of 100 total positions)" "the exact percentage … isn't recorded"
    What was the average framerate improvement with the Hardware-Aware Modular Training agent? (assistant detail) about 20% quotes the transcript: "approximately 20%" describes the paper, no number

    The first needs dates to pick the newer value. The second needs two facts from different sessions. The third needs the raw transcript, because the detail was in what the assistant said.

    A 3-to-0 split on discordant pairs is not statistically significant (McNemar exact p ≈ 0.25). The full 60-instance run is needed before drawing a conclusion.

    The comparison is between two whole systems, not two clustering methods. The episodic agent also receives session and question dates, gets the raw transcripts of its three closest memories (the tag agent sees only summaries), uses gemini-embedding-2 instead of gemini-embedding-001, and has a different answer prompt. Nothing here shows how much of the gain comes from the episodes themselves; a run with top_episodes=0 would isolate that.

    All 23 episodic instances that finished before the cap (including 7 with no valid tag-graph pair) scored 22 of 23. No LLM call fell back to degraded text in either run before the cap.

    Retrieval quality¶

    The JSONL records the session ids of the retrieved memories in rank order, so the rank of each session that holds the answer can be checked. Across the 23 valid episodic instances there are 43 answer sessions:

    Rank of the answer session Count
    1 22
    2 to 3 (transcript attached) 18
    4 to 12 3
    Not retrieved 0

    Whole-session embeddings already put the evidence at the top. On this sample, splitting sessions into chunks before clustering would not improve recall.

    Views experiment: separate linked views vs one unified tree¶

    Run on 2026-11-25 to test the plan in the unified memory plan: keep separate semantic (neural RAG tree), ontology (tags and entities) and episodic (timelines) views over the same dated memories and link them, or build one unified tree.

    Different models from the Gemini runs

    Every call (summaries, embeddings, answers, judge) used open models on a rented A100: Qwen3-30B-A3B-Instruct-2507-FP8 and Qwen3-Embedding-0.6B. The same Qwen model answers and judges, with LongMemEval's official judge prompts. Compare these numbers with each other, not with the Gemini tables above.

    Same 60 questions (10 per type, seed 42). All arms read the same built memory; they differ only in which views feed ranking and context.

    Arm What it uses Accuracy, 60K context Accuracy, 12K context
    F dated memories only, leaf ranking 0.825 0.702
    S + semantic view 0.842 0.719
    U + one unified tree 0.789 0.702
    E + episodic view 0.754 0.579
    O + ontology view 0.596 0.544
    M all three views, linked 0.632 0.561

    M lost to F on 14 questions and won 3 (exact McNemar p = 0.013 at 60K). U against F was even (5 wins, 6 losses). Link following changed nothing measurable.

    Why the linked views lost¶

    Each view's ranking was fused with the leaf ranking by equal-weight reciprocal rank fusion. That is what failed, not the view contents:

    View Leaf ranking had the answer in its top 3 Fusion pushed it out of the top 3 Answer missing from the view's list
    Ontology 57 16 15
    Episodic 57 15 0
    Semantic 57 3 1

    The ontology view only lists memories that share a label with another memory (median 24 of 48), so a one-off topic is absent from its list and loses under fusion. The episodic view orders memories by thread and recency rather than by relevance to the question. Because the full transcripts go to the top 3 fused memories, losing the answer from the top 3 costs accuracy directly.

    The test of views as extra context, with ranking left to the leaves, has not been run yet.

    Other findings¶

    • Tags and entities in the embedded text: no measurable effect on ranking (reciprocal rank 0.937 with, 0.933 without; recall@3 0.910 with, 0.939 without). They stay in the rendered memory lines.
    • Scoring nodes by the mean of their members' vectors ranked the answer's node higher than scoring by the embedding of the node's summary text, in all four views (for example episodic 0.972 against 0.899).
    • Noise floor: answering the unified arm a second time changed 0 of 60 verdicts.
    • Cost: $9.35 of GPU time in total. About $5 of that was an H100 started to speed the run up that never served a request.

    Raw rows, rules and the full summary: docs/benchmarks/views-experiment/full/.

    Why the earlier 0.87 headline is not comparable¶

    The README quotes 0.870 on the first 100 LongMemEval_S questions. The file is ordered by type, so the first 100 questions are 70 single-session-user and 30 multi-session questions. Those are the easier types; the first 100 contain no temporal-reasoning, knowledge-update, single-session-assistant or preference questions. Under the official judge that run scores 0.887. The stratified sample is the one to compare against.

    Reproducing¶

    uv sync --dev
export GEMINI_API_KEY=...

# Episodic memory
uv run python packages/neuromem-bench/scripts/run_longmemeval.py \
  --agent neuromem-episodic --per-type-sample 10 --seed 42 \
  --metric llm-judge --model gemini-3.8-flash --workers 4 --rpm 500

# Tag-graph memory
uv run python packages/neuromem-bench/scripts/run_longmemeval.py \
  --agent neuromem --per-type-sample 10 --seed 42 \
  --metric llm-judge --model gemini-3.8-flash --workers 4 --rpm 500

# Rescore any existing run with the official judge
uv run python packages/neuromem-bench/scripts/rescore_with_llm_judge.py \
  docs/benchmarks/<run>.jsonl

    Each run writes a JSONL file with one row per question. Each row includes the prediction, the judge's raw verdict, the rendered memory context, timings and, for the episodic agent, evidence recall. Raw files are in docs/benchmarks/.
