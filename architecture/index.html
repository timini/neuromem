    Architecture¶

    neuromem is long-term memory for LLM agents. Conversations go in, get consolidated in the background, and come back out as a compact context block the agent can read. This page describes how the code is laid out, how the two memory models work, how agents use them, and how the benchmark harness measures them.

    The design decisions behind this layout are recorded in the ADRs:

    ADR Decision
    ADR-001 Hand-rolled numpy clustering (later superseded in part by ADR-003)
    ADR-002 Centroids get placeholder labels at clustering time and LLM names later
    ADR-003 HDBSCAN clustering, per-centroid paragraph summaries, expand_node tool
    ADR-004 All LLM work moves to the background dream cycle; retrieval makes no LLM calls
    ADR-005 Episodic memory: dated whole-session memories and overlapping episode clusters

    Workspace packages¶

    The repository is a uv workspace. The root pyproject.toml has no [project] table; it declares members = ["packages/*"] and shared ruff, pytest and coverage settings. Each package under packages/ has its own pyproject.toml.

    Package Import name Owns Runtime dependencies
    neuromem-core neuromem Contracts, both memory models, SQLite storage, clustering, context rendering, agent tool functions numpy, pandas, hdbscan, scipy
    neuromem-gemini neuromem_gemini GeminiLLMProvider, GeminiEmbeddingProvider, a per-API-key token bucket (_rate_limit.py) neuromem-core, google-genai, numpy
    neuromem-openai neuromem_openai OpenAILLMProvider, OpenAIEmbeddingProvider; both accept base_url for any OpenAI-compatible endpoint neuromem-core, openai, numpy

    neuromem-adk neuromem_adk enable_memory for Google ADK agents, ADK callbacks, NeuromemMemoryService neuromem-core, neuromem-gemini, google-adk, numpy

    Each provider package ships its own prompt files under prompts/ (generate_summary.prompt, extract_tags_batch.prompt, generate_junction_summaries_batch.prompt and so on). Prompt wording is therefore a provider concern, not a core concern. The exception is EpisodicMemory, which owns its prompts in episodic.py and calls the provider's free-form complete(prompt).

    Layering¶

    neuromem-core has three layers. Orchestration code depends only on the contract layer. Concrete providers and storage are passed in through constructors.

    • Contracts: packages/neuromem-core/src/neuromem/providers.py defines EmbeddingProvider (get_embeddings), LLMProvider (summaries, tags, named entities, category names, junction summaries, complete) and ClusteringProvider (cluster) plus the Cluster record. packages/neuromem-core/src/neuromem/storage/base.py defines StorageAdapter, an ABC with 16 abstract methods covering memory rows, nodes, edges, nearest-node search, subgraph walks, decay and the access-weight spike.
    • Orchestration: system.py (NeuroMemory) runs the tag-graph pipeline. episodic.py (EpisodicMemory) runs the episodic pipeline. context.py (ContextHelper) and tools.py turn stored memory into text for an agent.
    • Adapters: storage/sqlite.py (SQLiteAdapter) and clustering.py (HDBSCANClusteringProvider, StubClusteringProvider) ship in core. LLM and embedding providers live in sibling packages.

    NeuroMemory.__init__ checks each injected object with isinstance against its ABC and raises TypeError on a mismatch. On LLMProvider only generate_summary, extract_tags and generate_category_name are abstract. The batch methods default to looping over the single-item method, and extract_named_entities and generate_junction_summary also have defaults, so a provider can start with the three abstract methods and add the rest later. LLMProvider.complete raises NotImplementedError by default; all four shipped LLM providers implement it.

    Two memory models¶

    Two memory models now exist side by side in neuromem-core. Both are exported from neuromem/__init__.py. They share the provider contracts but not storage or retrieval.

    NeuroMemory (tag graph) EpisodicMemory (episodes)
    ADRs 001 to 004 005
    Unit stored A text, or a session transcript via enqueue_session A session transcript with its date and session id
    What gets embedded Short LLM-extracted tag labels The whole memory: date, summary and transcript
    Hierarchy HDBSCAN over tag vectors, recursive scipy agglomerative dendrograms over memory vectors, several linkages
    Storage Any StorageAdapter (default SQLiteAdapter) Its own SQLite tables (ep_memories, ep_episodes)
    Consolidation trigger Background thread when the inbox reaches dream_threshold, or force_dream Explicit, blocking dream()
    Retrieval output ASCII tree of centroids, tags and memory snippets Dated text: episodes, memory summaries, raw transcripts
    Dates Not passed in Parsed, sorted on, rendered and fed to every prompt
    Decay and LTP Yes No

    NeuroMemory: the tag graph¶

    NeuroMemory in packages/neuromem-core/src/neuromem/system.py stores memories as rows and builds a graph of tag nodes (leaves), centroid nodes (clusters of tags) and edges. A memory links to its tags with has_tag edges. A centroid links to its children with child_of edges, weighted by the cluster's cohesion (mean pairwise cosine of its members).

    Constructor defaults:

    Parameter Default Effect
    dream_threshold 10 Inbox size that starts a background dream cycle
    decay_lambda 3e-7 per second Exponential decay rate of access_weight
    archive_threshold 0.1 Memories whose decayed weight falls below this are archived
    cluster_threshold 0.65 Validated and stored, but not read by the default HDBSCAN provider
    clusterer HDBSCANClusteringProvider() Pluggable clustering (ADR-003)

    enqueue(raw_text, metadata) inserts a row with an empty summary and returns its id. It makes no LLM call. If the inbox count is at or above dream_threshold and no cycle is running, it starts a daemon thread named neuromem-dream. enqueue_session(turns) joins the turns as role: text blocks separated by blank lines and calls enqueue with the result.

    _run_dream_cycle takes a non-blocking lock, so a second concurrent cycle returns immediately. Its steps:

    1. Read every inbox memory and set them to dreaming.
    2. _backfill_summaries: call llm.generate_summary_batch on memories without a summary and persist with set_summaries.
    3. llm.extract_tags_batch over the summaries.
    4. llm.extract_named_entities_batch and set_named_entities. Entities annotate the rendered rows; they do not feed clustering.
    5. _ensure_tag_nodes: embed only labels not already stored, in one get_embeddings call, and upsert them as leaf nodes.
    6. _run_clustering: pass every node in the label map to clusterer.cluster, then write each returned cluster as a centroid with a placeholder label (cluster_ plus the first 12 characters of the node's UUID) and child_of edges.
    7. Insert has_tag edges from each memory to its tag nodes.
    8. _run_all_centroid_naming: pass every centroid whose label still starts with cluster_ to resolve_centroid_names.
    9. _run_all_junction_summarisation: pass every centroid without a paragraph_summary to resolve_junction_summaries.
    10. storage.apply_decay_and_archive.
    11. Set the batch to consolidated.

    Steps 8 and 9 catch their own exceptions and log them, so a naming or summary failure does not fail the cycle. On any other exception the batch goes back to inbox and the exception is re-raised. Only the status change is undone. Summaries, named entities, nodes and edges written before the failure stay in storage; the next cycle reuses the stored summaries.

    HDBSCANClusteringProvider L2-normalises the embeddings, runs hdbscan.HDBSCAN(min_cluster_size=2, metric="euclidean", allow_single_cluster=True), emits one Cluster per label (noise points stay unclustered leaves) and recurses on the new centroids while a level produces at least two clusters, up to depth 8. Clusters come back children first, and _run_clustering raises ValueError if a provider breaks that order.

    Decay is computed in SQLiteAdapter.apply_decay_and_archive as access_weight * exp(-decay_lambda * t), where t is the time since last_accessed (or created_at). Archiving a memory deletes its has_tag edges, so it drops out of retrieval. retrieve_memories resets access_weight to 1.0 for consolidated memories (long-term potentiation, LTP).

    EpisodicMemory: dated episodes¶

    EpisodicMemory in packages/neuromem-core/src/neuromem/episodic.py has no tags. A memory is a whole session. ADR-005 gives the reasons: on the tag pipeline's seed-42 LongMemEval run most misses were not retrieval misses, dates never reached the system, summaries dropped assistant-side details, and memories appeared under several tags.

    Constructor defaults: db_path=":memory:", linkages=("average", "ward"), merge_threshold=0.97, max_episode_size=30, embed_chunk_chars=24_000, workers=16.

    enqueue and enqueue_session take timestamp and session_id. The timestamp is parsed by parse_session_date, which accepts the LongMemEval format (2023/05/20 (Sat) 02:21) and several ISO forms. Dated memories sort by timestamp; undated ones sort after all dated ones in insertion order. No LLM call happens on enqueue.

    dream() holds an RLock for the whole cycle and blocks the caller:

    1. _summarise_and_embed: summarise each inbox memory in parallel with MEMORY_SUMMARY_PROMPT, which receives the session date and asks for relative dates to be resolved to absolute ones. Embed Date + Summary + Transcript. The transcript is split into chunks so that each chunk plus its Date and Summary header fits in embed_chunk_chars (at least 1,000 transcript characters per chunk). Chunk vectors are normalised and averaged.
    2. _merge_near_duplicates: union-find over pairs with cosine similarity at or above merge_threshold. Each group becomes a unit whose canonical id is its earliest member. A unit with more than one member gets a merged summary from MERGE_PROMPT, regenerated only when its member set changes.
    3. _rebuild_episodes: for each linkage, build the full scipy dendrogram over unit embeddings (cosine distance, or Euclidean on normalised rows for ward). Every internal node with at least 2 and at most max_episode_size members becomes an episode; identical member sets across linkages are kept once. Episodes are keyed by a SHA-1 of their sorted memory ids. Existing keys are reactivated without an LLM call. New keys get a summary from EPISODE_PROMPT in a fixed TOPIC / CURRENT / HISTORY format, plus two vectors: the embedding of the summary text and the normalised mean of the member embeddings.

    An LLM failure or empty response in any of these steps falls back to deterministic text (the truncated transcript, or the concatenated records) through _complete_or, so one bad call does not fail the cycle. Other errors roll back uncommitted SQLite writes and re-raise. Each step commits when it finishes, so completed steps are kept and the next dream() redoes the rest.

    build_context(query, today=...) embeds the query once and scores units and active episodes by dot product with the normalised query vector. Defaults: top_memories=12, top_episodes=6, raw_memories=3, raw_chars=12_000, episode_embedding="summary" (or "mean", "max"), max_episode_overlap=0.8. An episode is skipped if its Jaccard overlap with a higher-ranked chosen episode exceeds 0.8. The rendered text has four parts: today's date, the chosen episodes, the chosen units in date order with their dates, and the raw transcripts of the closest units. It returns an EpisodicContext that also lists the memory, session and episode ids it used, which the benchmark uses for evidence recall.

    Hot path and background work¶

    ADR-004 splits NeuroMemory into a hot path that serves agent turns and a background path that does all LLM work.

    • Hot path: enqueue is one insert plus a count. ContextHelper.build_prompt_context makes one embedder call. expand_node makes no embedder call. retrieve_memories makes no model calls. None of them call the LLM once the dream cycle has finished.
    • Background: the dream cycle does summarisation, tagging, entity extraction, label embedding, clustering, naming and junction summaries.

    Memories only gain has_tag edges inside the dream cycle, so a memory in inbox cannot be reached by retrieval. In an agent this means the current session lives in the model's chat history and memory holds earlier sessions.

    resolve_centroid_names and resolve_junction_summaries still run inside build_prompt_context and expand_node. They return early when no node in the subgraph has a placeholder label or a missing summary. Otherwise they log a WARNING that the ADR-004 invariant is broken and do the work on the hot path. Naming makes one batched generate_category_names_batch call and persists with update_node_labels. Summarising makes one generate_junction_summaries_batch call per tree level, children before parents, and persists each level with update_junction_summaries. If batched naming fails, each centroid takes the label of the child closest to its embedding (ADR-002). If batched summarising fails or returns an empty summary, llm.generate_junction_summary is called for the affected centroids (ADR-003). Both public methods catch and log any exception, so rendering never fails because of them. The dream cycle calls them with flags that suppress the warning.

    EpisodicMemory does not follow this split yet. Its dream() is synchronous and must be called by the owner before build_context will see new memories. build_context itself makes one embedder call and no LLM calls.

    Agent integration¶

    There are three ways for an agent to use NeuroMemory.

    Passive injection¶

    ContextHelper.build_prompt_context(task, top_k=5, depth=3) in context.py builds the context block. It embeds the task, takes the top_k nearest nodes with storage.get_nearest_nodes (a single numpy cosine pass over all nodes), walks get_subgraph to depth hops, caps the result at 80 nodes with _enforce_node_cap (seed nodes are never dropped; other nodes are ranked by hop distance from the nearest seed over child_of edges and the farthest are dropped, along with memories that lose all their tags) and renders an ASCII tree with _render_ascii_tree. Memory snippets are capped at 300 characters and junction summaries at 400. It returns an empty string when nothing is found.

    Tool functions¶

    The functions in tools.py take the NeuroMemory instance as an argument so a wrapper can bind it:

    Function Defaults Behaviour
    search_memory(query, system, top_k=5, depth=2) depth 2 Calls build_prompt_context with these arguments
    retrieve_memories(memory_ids, system) Returns full rows including raw_content; unknown ids are skipped; consolidated rows get the LTP spike
    expand_node(node_id, system, depth=2) depth clamped to 5 Renders the subtree under one node with the same 80-node cap; no query embedding, no LTP

    Google ADK¶

    neuromem_adk.enable_memory(agent, db_path, ...) in packages/neuromem-adk/src/neuromem_adk/enable.py wires all of this into a Google ADK Agent in place and returns the NeuroMemory:

    • Providers default to GeminiLLMProvider and GeminiEmbeddingProvider, built from GOOGLE_API_KEY or GEMINI_API_KEY. Either can be overridden. cluster_threshold and dream_threshold are forwarded only when given.
    • before_model_callback gets build_before_model_context_injector: it takes the current user text, calls build_prompt_context, and appends the tree to llm_request.config.system_instruction.
    • after_agent_callback gets build_after_agent_turn_capturer: it enqueues the user text and the latest assistant text as two memories with role and turn metadata.
    • Three tools are appended to agent.tools: search_memory_tool, retrieve_memories_tool, expand_node_tool. They are plain wrapper functions so ADK's schema generator does not see the system argument.
    • Existing callbacks are kept: _chain_callback turns the slot into a list with neuromem's callback last. A second call on the same agent raises ValueError.

    NeuromemMemoryService in memory_service.py implements ADK's BaseMemoryService. add_session_to_memory enqueues every text event and then calls force_dream(block=True); search_memory parses memory ids out of the rendered tree and returns them as MemoryEntry objects. enable_memory does not install it.

    EpisodicMemory has no tool functions or ADK wiring yet. The benchmark calls it directly.

    Benchmark harness¶

    neuromem-bench runs published memory benchmarks against interchangeable agents. LongMemEval is the only dataset loader so far.

    Datasets¶

    datasets/base.py defines BenchTurn, BenchSession (with timestamp), BenchInstance (question, gold answer, question type, metadata) and the Dataset ABC. datasets/longmemeval.py (LongMemEval) downloads longmemeval_s_cleaned.json, longmemeval_m_cleaned.json or longmemeval_oracle.json from the xiaowu0162/longmemeval-cleaned Hugging Face dataset into ~/.cache/neuromem-bench/ (or NEUROMEM_BENCH_CACHE). Each instance keeps its haystack session ids and dates, and stores question_date and answer_session_ids in metadata.

    Agents¶

    agent.py defines the BaseAgent protocol: process_session(turns, *, timestamp, session_id), answer(question, *, question_date), reset().

    Agent Memory Answer path
    NullAgent Last 50 turns One Gemini call with the turns in the system prompt
    NaiveRagAgent One embedding per turn Top 5 turns by cosine similarity
    NeuromemAgent NeuroMemory, dream_threshold=9999, cluster_threshold=0.55 force_dream, then build_prompt_context(top_k=20), then one Gemini call
    NeuromemAdkAgent enable_memory with the same thresholds force_dream, then an ADK Runner with the injector and three tools
    NeuromemEpisodicAgent EpisodicMemory with gemini-embedding-2 dream(), then build_context(today=question_date), then one Gemini call with prompts/episodic_answer.prompt

    NeuromemAgent and NeuromemAdkAgent ignore session timestamps and the question date. NeuromemEpisodicAgent passes both through. The answer model for the one-shot agents is GeminiAnsweringClient in _client.py. _providers.py builds the memory-side provider pair for gemini, openai, anthropic or gemma.

    Runner¶

    runner.py (run_benchmark) calls _run_one_instance for each instance: reset, process_session for each session in order, answer, then _score_prediction. Agents may expose last_trace and last_tool_calls; these are copied into the result row. If the trace has retrieved_session_ids, _evidence_recall records the fraction of the instance's answer sessions that reached the context. A metric exception keeps the prediction and records metric_error. With workers > 1 each thread builds its own agent from agent_factory. Results stream to JSONL and a Markdown summary with a per-question-type table is written next to it.

    Metrics¶

    metrics.py has exact_match, contains_match (normalised substring), llm_judge (a generic single-prompt judge) and longmemeval_judge. longmemeval_judge uses the per-type judge prompts copied from LongMemEval's official evaluator: separate templates for temporal reasoning (off-by-one days allowed), knowledge update (the updated answer must be present), preference (rubric) and abstention (instance ids containing _abs). It runs at temperature 0 and counts a verdict as correct when it contains "yes". The default judge model is gemini-3.8-flash.

    Command line¶

    packages/neuromem-bench/scripts/run_longmemeval.py selects agents (null, naive-rag, neuromem, neuromem-adk, neuromem-episodic), the metric (--metric llm-judge uses longmemeval_judge), --judge-model, --per-type-sample N with --seed for a stratified reproducible sample, --workers and --rpm. All Gemini clients on one API key share one token bucket. scripts/rescore_with_llm_judge.py re-judges an existing JSONL with the official prompts without re-running the agent.
